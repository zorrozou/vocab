# 双端一致性清单（网页版 ⇄ iOS App）

> 2026-10-08 起生效。用户明确要求：**网页端和 App 端功能完全一致**。
> 本清单是强制约束：任何一端改动学习逻辑，另一端必须同一次提交跟上。

## 铁律

1. **学习状态 schema 一致**：`LearningState`（iOS）= `defaultState()`（web）字段级同构；新增字段必须双端同时加，且可选字段要容错解码（旧存档不炸）
2. **一次提交双端齐改**：学习逻辑（调度/定级/调速/同步/文案口径）不允许只改一端
3. **"今天"口径一致**：两端都用设备本地日期（不用 UTC）
4. **FSRS 单一事实源在服务端**：两端都只调用 `/api/v1/fsrs/review`，不各自实现调度

## 已知差异（有意为之，不追平）

- 跟读交互：iOS 按住说话（微信式）；web 点击开始/结束（浏览器限制）
- 音频缓存：iOS 有本地磁盘缓存；web 依赖浏览器缓存
- 提前巩固概率池的抽取是各自随机（无状态同步需求）

## 回归检查动作（改完任一端必做）

1. `grep` 本清单涉及的关键函数名，确认双端行为一致
2. 模拟器/浏览器各跑一遍：定级→学习→复习→验收→完成页
3. 双端 state JSON 互读无损（用对方端 pull 一次验证）
