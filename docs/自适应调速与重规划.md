# 自适应水平追踪设计（v1.2 提案 · v2）

> 2026-09-24 · 状态：设计稿 v2（用户纠偏后重写），待评审
> 用户原话："不是发新词多少的问题。新词一直都是 10 个。而是根据每个词熟悉/不熟悉的反馈，动态判断用户目前的实际词汇量水平，动态调整之后给用户学习的词汇是哪个级别的。"

## 0. 核心思想

**把定级测试的贝叶斯估计器从"一次性快照"变成"常驻在线追踪器"。**

定级时我们已经有了一个词汇量后验网格（0~12000，步长 250）。定级结束后它不归档——之后学习过程中的**每一个词的每一次反馈，都是对这个后验的一次新观测**，水平估值随证据持续漂移；新词的发词位置跟着估值走，而不是死板地从定级那天定下的位置每天 +10。

约束不变式：**FSRS 逐词记忆调度完全不动**（它管"何时复习"，本设计管"从哪发词"，两层解耦）。

## 1. 在线估计器（复用定级的观测模型）

观测模型沿用定级的 logistic 响应函数：

```
P(认识 | 水平 L, 词位 r) = logistic((L − r) / 400)
```

每次观测 `(词位 r, 会不会 resp, 权重 w)` 后，后验按**带权似然**（likelihood tempering）更新：

```
posterior[i] ∝ posterior[i] × likelihood(grid[i], r, resp)^w
```

权重让"客观测试"比"自评按钮"说话更算数，"遗忘"比"不认识"说话更小声。

## 2. 信号与权重表（全部来自现有埋点，零新增采集）

| 事件 | 证据含义 | resp | 权重 | 理由 |
|---|---|---|---|---|
| 新词卡点「不熟悉」 | 这词不认识 | 0 | **1.0** | 自评"不会"基本可信 |
| 验收测试答对 | 这词真会了 | 1 | **1.0** | 客观实测 |
| 验收测试答错 | 这词没会 | 0 | **1.0** | 客观实测 |
| 新词卡点「学会了」 | 自称会了 | 1 | 0.5 | 自评偏乐观，且当天还有验收复核 |
| 复习 4 选 1 答对 | 会且记得 | 1 | 0.3 | 记忆与水平的混合证据 |
| 复习 4 选 1 答错 | 多半是没记住 | 0 | 0.2 | 遗忘 ≠ 不认识，弱证据 |

水平估值 = 后验均值；置信度 = 后验标准差（std 越小越确定）。

## 3. 发词位置规则（核心）

两个概念分离：

- **pointer**（物理游标）：词库长龙里"发到哪儿了"，**只前进不后退**，发过的词永不重发
- **T**（目标位）：后验均值指示的"当前应该在的位置"——学在水平边界上，才有新东西可学又不至于全不会

每日 `buildQueue` 时：

```
if  T − pointer > 500  且  std < 800:   # 水平明显跑在游标前面（这级别对你太简单）
    pointer 跳到 T                        # 追平：中间的词视为已会，直接跳过
elif pointer − T > 500  且连续 2 天:     # 游标跑在水平前面（近期词太难）
    不后退（已发的词 FSRS 在管）
    新词降到 5 个/天，直到 T 追上来         # 减压阀：少发点，先消化
else:
    pointer 照常前进（每天 10 个新词位）
```

效果：
- 学得顺（验收天天对）→ 后验均值持续上漂 → pointer 自动大步向前跳——**级别"升档"是自然发生的，不需要任何跳级测试**
- 学得难（连续不熟悉/验收错）→ 估值回落 → 游标超前后自动减压——**降难度也是自然发生的**
- v1 设计里的"跳段测试/回落卡片"全部废除，被连续追踪取代

防震荡：pointer 只前进；跳跃要同时满足"差距 500 + 置信足够"；每日最多生效一次位置重估。

## 4. 重新定级 = 先验刷新（而非另起炉灶）

- 重测 30 题完成 → posterior 换成新定级结果、frontier 更新、pointer = 新 frontier
- 存量卡片 FSRS 一律不动；pendingNew 清理规则：
  - 新边界更高：30 天前的旧探测错词丢弃（水平已变，不追旧账）；其余保留
  - 新边界更低：全部保留（真实薄弱词）
- 之后在线追踪器接着跑——**定级只是给估计器换个新起点，不再是一锤定音**

## 5. 与既有功能的兼容保证

| 既有功能 | 影响 |
|---|---|
| FSRS 逐词调度（/fsrs/review） | **零改动** |
| 新词固定 10 个/天 | 默认不变；只在"游标长期超前于水平"时减压到 5 |
| 复习两段卡 / 当日验收 / 个性化例句 / 提前巩固池 | 零改动（它们的数据被追踪器读取而已） |
| dailyCap、复习优先 | 不变 |
| 跟读 / 音频 / 多用户 / 同步 | 无交集 |

## 6. 实现要点（动手时）

1. `StudyEngine.posteriorUpdate` 加 weight 参数（`like^w` 后归一化），定级流程传 1.0 行为不变
2. 埋点：learn（学会/不熟悉）、验收对错、复习对错 → 各调一次观测
3. `AppState.trackLevel()`：算 T、判定跳位/减压，写 `S.track = { mean, std, lastJumpDay, lowSince }`
4. `buildQueue` 的发词起点改用 trackLevel() 输出（替代固定 pointer）
5. `S` 新字段 `track`（Codable 可选，旧存档兼容）；web 端同名对齐
6. 完成页透明化一句："系统判断你的词汇量 ≈4233（四级），明天从这里发词"
7. 阈值参数（500/800/2 天/5 词）集中常量表，后续按真实数据调

## 7. 边界情形

- **自评与实测打架**：验收权重高于"学会了"，客观结果覆盖当天自评
- **观测用精确词位 pos**（比 L1~L6 段位细），级别名只是展示
- **日期口径**：全部本地日期（上一轮 UTC 修复的口径）
- **多端同日**：state 以服务器最新为准，不合并（与现有一致）
