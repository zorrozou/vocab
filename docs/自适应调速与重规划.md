# 自适应调速与重规划设计（v1.2 提案）

> 2026-09-23 · 状态：设计稿，待评审
> 目标：让学习节奏随学习者状态动态调整；**FSRS 逐词记忆调度完全不动**。

## 0. 分层职责（关键约束）

| 层 | 职责 | 是否变化 |
|---|---|---|
| FSRS（现有） | 每张卡片的复习时机（when）——D/S/R 三态、四档评分 | **完全不变** |
| 调速器（新增） | 每天发多少新词、从什么位置发、是否跳段/回落（what & how many） | 新增，只读 FSRS 的表现数据 |

调速器是纯"读 FSRS 日志 → 输出明日配额/位置"的旁路控制器。它永远不会改卡片的 due/stability——生词记忆功能因此保证无变化。

## 1. 信号（全部来自现有 log，零新增采集）

| 信号 | 来源 | 口径 |
|---|---|---|
| 验收通过率 | 当日验收测试 | rating≥3 / 当日验收总数 |
| 复习答对率 | 复习 4选1 + 评分 | rating≥3 / 复习总数 |
| 薄弱词数 | 当日 rating≤2 去重 | 已有（个性化例句用同一口径） |
| 每日完成量 | log | 复习数 + 新词数 |

滚动窗口：**最近 3 天**（不足 3 天用实际天数，首日不调速）。

## 2. 调速器规则（每日完成页结算时算明日配额）

### 2.1 每日新词量动态化（替代固定 10）

```
mastery = 近3天验收通过率；health = 近3天复习答对率
if  mastery ≥ 90% 且 health ≥ 85%:  明日 newPerDay += 2   # 提速
elif mastery < 70%  或 health < 70%:  明日 newPerDay -= 3   # 降速
else:                                  不变
硬边界：[5, 20]；用户手动设置覆盖当天，次日调速器再接管
```

理由：新词量的正确上限取决于"今天学的明天还记得多少"，验收通过率就是它的直接测量。复习答对率是遗忘压力的反向指标。

### 2.2 跳段（Skip-ahead）——超出当前级别的快速通道

- **触发**：连续 3 天 验收≥95% 且复习≥90%（稳定驾驭当前级别）
- **动作**：弹一次"跳级测试"卡片——从当前级别剩余未学词里随机抽 10 个做 4 选 1：
  - 错 ≤1：pointer 直接跳到**当前级别末尾 +1**（即下一级起点）；跳过词不入学
  - 错 ≥2：不跳，错词进 pendingNew 优先补学
- **节流**：每 30 天最多 2 次跳段；跳段后 3 天观察期内不再触发

### 2.3 回落（Step-back）——明显学不会时主动降难度

- **触发**：连续 2 天 验收通过率 <50%
- **动作**：完成页弹提示卡，二选一：
  - 「回到段首巩固」：pointer 回退到当前级别起点，区间内未掌握的词按新词重学
  - 「重新定级」（跳设置页重测 30 题）
- 回落后 3 天观察期：只复习不发新词过多（newPerDay 压到 5）

### 2.4 透明性

每次调速写一条日志 `{d, kind:"pace", action:"speed_up"/"slow_down"/"skip"/"fall_back", detail}`，
完成页展示一句人话："近三天你新词验收 96%，明天给你 14 个新词"。学习者知道系统为什么这么安排。

## 3. 重新定级后的重规划（呼应"重测后应重新规划"）

现状盘点：目前的重新定级只做了 `frontier=pointer=新边界`，**存量卡和 pendingNew 没有重规划**——这正是"目前不是这个逻辑"的缺口。补全规则：

设旧边界 F，新边界 F'：

1. **pointer = F'**：新词从新边界发（已有）
2. **pendingNew 清理**：
   - F' > F（测得更高）：pendingNew 中位置 < F' 的探测词，若上次定级答错距今 >30 天则丢弃（水平已变，旧错题不追）；其余保留
   - F' < F（测得更低）：全部保留（这些是真实薄弱词）
3. **存量卡片**：
   - F' > F：位于 [F, F') 区间、已学过的卡保持 FSRS 不动（它们确实是学过的）；区间中从未学过的词不再追（假定已会）——即不补学缺口
   - F' < F：不动任何卡片；[F', F) 区间里"学过未掌握"的卡由 FSRS 继续复习，"未学过"的词随新 pointer 正常学到
4. **定级后首日调速器以观察模式运行**（新边界的第一批新词还没验收数据，3 天后才恢复调速）

## 4. 与既有功能的兼容保证

| 既有功能 | 影响 |
|---|---|
| FSRS 逐词调度 | 零改动（服务端 /fsrs/review 照旧） |
| 复习 4选1→评分两段卡 | 零改动（只是答题数据被调速器读取） |
| 当日验收测试 | 零改动（它的通过率是调速器核心输入） |
| 个性化例句（薄弱词定制） | 零改动（薄弱词口径一致） |
| 每日上限 dailyCap、复习优先 | 不变；调速只改 newPerDay 有效值 |
| 跟读/音频/多用户/同步 | 无交集 |

## 5. 实现要点（后续动手时）

- `AppState.computeTomorrowPace()`：在 DoneView 结算时运行，写入 `S.pace = { tomorrowNewPerDay, lastPaceAction, ... }`；`buildQueue` 用它替代 `S.settings.newPerDay`
- 跳段测试复用 `/api/v1/quiz`（按级别区间抽位置出题），无需新端点
- 重规划逻辑集中在 `AppState.replanAfterPlacement()`，`finishPlace` 完成后调用
- `S` 新增字段：`pace: PaceState?`（Codable 可选字段，旧存档兼容）——web 端 LearningState 同名字段对齐
- 全部规则参数（阈值/步长/节流）放常量表，方便后续按数据调参

## 6. 不做的事（本期明确排除）

- FSRS 参数个性化拟合（那是 v1.5 的事，且与本设计互补）
- 根据跟读分数调速（发音分暂不进入节奏决策）
- 跨设备配额博弈（多端同日学习时按服务器 state 最新值为准，不做合并）
