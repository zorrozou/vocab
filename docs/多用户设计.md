# 多用户功能设计（待评审）

> 版本：v1.0（评审稿） · 日期：2026-09-03
> 现状基线：Web 单页应用，学习状态存浏览器 localStorage，个性化例句按匿名 deviceId 区分（服务器 personal.db 已有 10 个设备）

---

## 1. 目标与范围

- 支持**多个用户**在同一系统（当前 Web 页 + 未来 iOS App）各自学习
- 每个用户独立的：定级结果、学习卡片、复习记录、薄弱词、个性化例句、统计、设置
- 同一浏览器/设备上可**切换用户**；账号在**任意设备登录后可继续进度**
- 不破坏现有匿名体验：游客可先用，注册后可把游客进度并入账号

**本期不做**：社交、排行榜、班级/教师端、付费。

## 2. 用户模型与认证

### 2.1 账号体系（v1 先行，iOS 预留）

| 方式 | 本期 | 说明 |
|---|---|---|
| 用户名 + 密码 | ✅ | 最简；密码只存 PBKDF2/bcrypt 哈希 |
| 邮箱验证码 | ❌ 延后 | 需要邮件服务 |
| Sign in with Apple | ❌ M1 时接入 | iOS 上架硬性要求（若提供其他第三方登录则必须提供它） |
| 微信/手机号 | ❌ 延后 | 需企业资质/短信通道 |

### 2.2 认证机制

- 注册/登录成功 → 服务器签发 **Bearer token**（随机 32 字节，HMAC 签名或查表），有效期 30 天，滑动续期
- 页面持有 token 于 localStorage；所有用户数据请求带 `Authorization: Bearer <token>`
- 登出 = 服务端吊销 token
- 服务器端点分级：`/lexicon/*`、`/quiz`、`/tts`、`/placement/*` 保持公开（内容数据）；`/me/*`（进度、个性化）必须带 token

## 3. 数据归属与同步策略（沿用已定稿原则：执行在本地，数据可同步）

```
浏览器 localStorage（工作态，毫秒级读写，离线可用）
      ↕ 变化后 2 秒防抖批量推送 / 打开时拉取
服务器 users 库（权威副本，多端一致 + 换机恢复）
```

- **本地优先**：学习交互永远读本地，断网不影响；联网时后台静默同步
- **冲突合并**：cards 按 `due/stability` 取较新（last_write_wins on per-card basis），log 是 append-only 合并去重
- **首次登录迁移**：游客已有 localStorage 进度 → 注册/登录后询问"保留当前进度到账号？"→ 是则整体上传
- **个性化例句归属**：personal.db 的 `device` 字段改为 `user_id`（旧 device 数据做一次映射迁移或保留兼容查询）

## 4. 服务器端点设计（新增 `/me` 前缀）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/v1/auth/register` | POST | 用户名+密码注册（校验唯一性、密码强度）→ token |
| `/api/v1/auth/login` | POST | 登录 → token |
| `/api/v1/auth/logout` | POST | 吊销当前 token |
| `/api/v1/me/state` | GET | 拉取该用户全量学习状态（cards/log/settings/placement/个性化） |
| `/api/v1/me/state` | PUT | 推送本地状态（防抖批量；字段级合并） |
| `/api/v1/me/sentences` | GET | 该用户的个性化/巩固例句（按日期） |
| `/api/v1/personalize` | POST | 改为 token 识别用户（替代 device 参数） |

**服务器存储**（`users.db`）：
- `users(id, username UNIQUE, password_hash, created_at, last_login_at)`
- `tokens(token_hash, user_id, expires_at, revoked)`
- `user_state(user_id, cards_json, log_json, settings_json, placement_json, updated_at)`（JSON 列存整体状态，单用户体量小，无需拆表）
- `personal.db` 的 `device` → `user_id`（兼容期双写）

## 5. 页面流程改造

```
启动
 ├─ 有 token 且有效 → 静默拉取进度 → 直接进入今日任务
 ├─ 无 token → 欢迎页：「登录 / 注册 / 先逛逛（游客）」
 │    ├─ 游客 → 现有 localStorage 流程不变
 │    └─ 注册/登录成功 → 若游客有进度 → 询问是否并入 → 上传/拉取
 └─ token 失效 → 提示重新登录（本地进度保留）
```

**头部区域**：用户名 + 切换/登出入口；游客显示"未登录（进度仅在本机）"提示。

## 6. 隐私与安全

- 密码哈希：PBKDF2-SHA256（10 万次迭代）或 bcrypt，绝不存明文
- token：只存哈希，传输必须 HTTPS（**前置依赖：先解决证书**——目前 IP+HTTP 裸奔，多用户涉及账号安全，HTTPS 成为 P0 前置）
- 限流：登录/注册接口 IP 级限流（fail2ban + 端点级速率）
- 用户名唯一性、最小长度、密码最少 8 位
- 不提供"找回密码"（v1 无邮箱通道；v1 提供"联系管理员重置"的人工通道即可，用户量小）

## 7. 分阶段里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| **M-U1 账号体系** | users/tokens 表 + 注册/登录/登出 + token 中间件 | curl 全流程通；错误密码/重复用户名正确拒绝 |
| **M-U2 进度同步** | `/me/state` 推拉 + 本地防抖推送 + 首次迁移合并 | A 浏览器学习 → B 浏览器登录同账号 → 进度一致 |
| **M-U3 页面接入** | 欢迎页/登录/注册/切换用户/游客模式 | 双用户同浏览器互切互不串数据 |
| **M-U4 个性化迁移** | personal.db device→user_id 兼容层 | 老设备数据按映射保留 |
| **M-U5 iOS 预留** | Sign in with Apple 接口占位（M1 时启用） | — |

## 8. 验收标准

1. 两个用户在**同一浏览器**先后登录：各自定级/学习/复习/薄弱词/个性化例句完全隔离
2. 用户 A 在浏览器 1 学 10 词 → 浏览器 2（或隐身窗口）登录 → 进度一致
3. 断网可继续学；恢复联网后静默同步，无冲突弹窗
4. 游客进度注册后可并入；未注册游客换浏览器则重新开始（预期行为，文案告知）

## 9. 开放问题（已于 2026-09-03 拍板）

1. **游客模式：保留** ✅（降低首次门槛；游客进度仅本机，注册后可并入）
2. **用户名仅 ASCII**（字母/数字/下划线，3~20 位）；**昵称允许中文**（仅展示用）
3. **HTTPS 本期不做**（沿用 IP+HTTP；明文密码传输风险已知悉并接受，上生产前必须补）
4. **找回密码：不做**（v1 管理员手动重置）
