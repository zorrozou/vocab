# 增量同步：实施约束与验收

## 实验性超限历史整理

服务器启用实验能力时，Web 和 iOS 可整理已有可信同步基线的超限状态。客户端先同步并调用只读预览，服务器验证版本、待重放评分和历史证据；预览成功不保证提交时服务器仍未变化。确认后客户端持久化账号专属整理意图及整理前视图，再以代次、基线修订、恢复版本和随机批次提交。服务器同一事务备份原状态、压缩已验证历史、推进恢复版本及修订、写入重置日志和幂等回执。客户端按回执校验固定快照、参数与服务器水位，保存旧视图并安装新视图及增量基线后解除栅栏；响应丢失时重试同批次。数据库恢复轮换代次时清除整理回执。

Web 浏览器与 iOS 模拟器分别在服务器提交后终止并重启，验证重试不重复提交及整理前备份保留；Swift 读取 Web 整理结果，Web 读取 iOS 整理结果。此能力仍受 14 MiB 实验状态和本机记录容量限制，客户端与服务端均会物化完整状态；预览后其他设备写入、历史过期或回执失效时保留本机和待处理记录，不能自动解决冲突。物理断电、真机、真实网络、旧客户端混用及内存和耗时仍需验证；实验开关保持默认关闭。

### 取消未提交的超限恢复或整理

用户可请求取消待处理的超限备份恢复或历史整理。服务器在同一写事务中检查批次回执和当前代次、修订及恢复版本：若操作已经提交则拒绝取消；若尚未提交且修订未前进，则在不改变学习状态的情况下推进修订并写入空变更，从而让迟到的原请求无法提交；若其他写入已推进修订，保留该写入并直接确认取消。恢复取消还须核对备份摘要，并在同一事务中清除匹配的暂存及分片。数据库恢复换代、恢复版本变化或本机记录不一致时保留栅栏并要求导出核对。取消与提交并发时由事务决定唯一结果。

Web 在服务器确认后以严格事务比较并删除操作意图，保留原主状态和基线；普通账号迁移中断时先完成可重复的迁移清理。iOS 在清理意图与保护文件前保存可重试的取消日志，最后清除此日志，期间始终阻止普通同步。响应丢失时重试取消；取消成功后的普通同步读取空变更或其他设备的后续变更。浏览器及 iOS 模拟器覆盖进程终止与重启；进程终止不等于物理断电，旧客户端混用、真机和真实网络仍需验证。实验开关保持默认关闭，服务器仍整体物化状态并受 14 MiB 上限约束。

## Web 首次建立增量基线失败的保护

Web 从返回代次和修订号的服务器加载普通状态时，在异步获取快照之前先保存账号专属同步标记。快照创建限流、网络错误、清单或内容无效、分页读取失败以及进程中断后，缺少基线的标记会阻止退回无版本保护的整包上传；本机修改仍可导出，用户可在设置中确认重新加载服务器状态，当前本机状态会先备份，然后重试同步。仅快照创建接口本身返回 404 时，首次创建的标记才可解除以兼容旧服务；已创建快照的分页返回 404 不属于该情况。首次快照下载期间产生的本机修改不再阻止原始基线安装；基线按原始已同步视图建立，后续修改通过增量同步上传。兼容旧服务的路径无法提供新协议的版本保护。普通账号仍使用 localStorage 保存主状态和标记，浏览器不能请求其立即持久落盘：隔离测试中保存后立即或约 2.5 秒后强制终止浏览器均曾丢失这些写入；约 8 秒后的一次测试保留了写入并可恢复，但等待时间不构成持久性保证。应将主存档、标记和保存确认迁入支持严格持久化的事务存储，才能处理这一缺口。

## 普通账号严格存储基础

新增独立的普通账号 IndexedDB 存储基础，使用严格持久化事务写入状态、账号、同步代次/修订/恢复版本、脏标记和摘要；写入前核对完整旧记录，普通保存不能改变同步版本或将未同步修改标为已同步。记录校验失败时可读取原始记录，不能以旧副本覆盖损坏或并发写入的记录。真实浏览器专项在确认事务完成后立即终止主进程，再重启并验证记录、两页面竞争、写入故障和账号隔离。测试只覆盖存储组件；它尚未接入普通学习保存、启动、账号切换、同步、备份或恢复，旧 localStorage 槽位也未迁移。因此现有用户仍面临未同步修改丢失风险，事务确认前的操作和物理断电亦未证明安全。

## 普通账号迁移候选与新主记录准备

新增迁移准备组件：持有账号和同步锁时，将旧槽位原文、完整旧增量记录及同步时钟一起写入严格持久化的候选记录并附摘要；保留旧存储，不将候选当作活动账号。另一准备步骤再次核对旧记录和候选，将新主记录写入严格事务，保留原代次、修订和恢复版本；本地内容或时钟显示未同步时必须保留脏标记。存在待发送批次或待安装下载时，候选保留原始证据，但不准备新主记录。重复准备相同数据可安全重试，内容不一致不能覆盖。浏览器专项覆盖旧页面竞争、写入失败、待发送记录及事务完成后立即终止进程。

这些步骤尚未接入真实用户流程；新主记录和候选共存时仍由旧槽位负责，不能仅凭新记录自动激活。旧页面不遵守新锁，候选写入或准备完成后旧数据仍可能变化，正式切换必须重新核对、处理待同步操作并保留可重试的清理记录。当前不会删除旧数据，也不能宣称现有用户的保存已可靠或立即中断不会丢失。

## 普通账号新主存档与同步基线的原子准备

普通账号存储升级后，准备阶段在同一个严格事务中写入新主存档及其完整旧增量基线，并通过本机版本和迁移候选标识绑定；旧版已准备但缺少新基线的记录，只有旧来源和候选仍一致时才可重复准备补齐。读取时在同一事务取得三项记录，逐项验证摘要、版本、账号、恢复版本和脏状态。后续本机编辑可在一个严格事务中同时更新主存档和基线绑定，原候选及旧基线保留为恢复证据；竞争写入或任一写入失败不会留下半套更新。普通单记录写入不能绕过迁移保护。

浏览器专项覆盖同步记录写入故障回滚、缺失基线、错误版本、错误清洁标记、并发编辑及事务确认后立即终止进程。这仍是内部准备和保存组件：尚未启用普通账号启动切换、学习界面的异步保存确认、上传/下载及恢复流程。旧 localStorage 存档仍是当前实际用户的数据来源，未同步修改丢失风险尚未解决。

## 普通账号准备记录的增量上传组件

内部普通账号适配器可使用普通增量接口：在发送前以严格事务保存完整待发送批次；收到回执后核对批次、版本并读取服务器变更，再以严格事务同时更新主存档、同步基线与待发送状态。重试沿用原批次；读取时检查待发送操作与保存的目标一致。旧槽位、旧同步记录或时钟变化时停止，写入失败和服务器冲突保留待发送记录。专项在服务器提交后丢失回复、立即终止浏览器并重启，以原批次确认结果；Swift 同步组件可读取上传结果。旧 localStorage 槽位在该测试中先等待约 8 秒以便观察既有副本，不表示其具备严格持久性。

该适配器尚未接入普通账号启动、学习界面和同步入口；服务器基线冲突、日志过期、缺少分片或需要整包合并时仍保守停止，未实现完整冲突合并及增量下载。旧槽位仍是当前真实用户的活动存档；该内部测试不能证明用户端数据丢失风险已解决，也不能替代真机、物理断电和完整双端回归。

## 普通账号准备记录的增量下载组件

内部下载组件只在新主记录无未同步修改、没有待发或待安装批次且旧槽位及旧同步证据仍与迁移候选一致时运行。它按代次、恢复版本和固定水位验证分页变更，解析所需评分参数，再以严格事务同时安装新主记录和同步基线；本机记录或账号在下载期间变化时拒绝覆盖。事务完成后再次检查旧来源，若旧来源变化则保留下载结果并要求核对。测试覆盖变更页损坏、事务故障、账号切换、并发本机编辑及事务确认后立即终止浏览器；Swift 同步组件写入的增量也由 Web 读取。

组件尚未接入普通账号启动或界面，旧槽位仍为实际用户的活动存档；日志过期、待发送冲突以及旧客户端绕过锁时仍需保守处理。隔离测试为旧 localStorage 副本预留等待时间，不证明其严格持久性，物理断电和完整双端界面流程尚未验证。

## 普通账号不同词卡冲突重放

内部普通账号上传遇到基线冲突时，仅当待发操作都是不同词条的完整词卡写入、这些词卡在旧服务器基线与旧本机视图一致、服务器没有修改相同词卡且所有非词卡状态与旧基线完全一致时，才可读取并核对服务器变更，将新服务器基线与原本机修改以严格事务保存，再用新批次重试。旧批次收到基线冲突后无法在单调递增的同代次旧修订上提交；重放前逐个验证服务器变更版本，避免词卡或其他字段先变化又恢复原值而掩盖旧回执已过期的可能。若重建基线或新批次保存中断，已保存的原本机修改仍保持待同步。回复丢失后重试同一新批次。

同词卡、其他字段变化、旧基线与本机词卡不一致、日志过期以及服务器对缺失字段补齐默认值等无法证明独立的情况仍保守拒绝并保留待发记录。跨端专项使用 Swift 写入另一词卡，浏览器在重建基线后及服务器提交后分别强制终止并重试。该路径仍未接入普通用户界面；旧槽位在隔离测试中经过等待，其 localStorage 持久性、旧页面混用、完整冲突合并和物理断电仍未解决。

## 普通账号切换栅栏与启动保护

内部切换准备在账号和同步锁内校验准备记录、旧槽位和同步证据，先写账号专属本地标记，再以严格事务记录切换栅栏；失败时回滚本次标记。新页面启动或登录后检查本地标记和 IndexedDB 栅栏，检查期间冻结页面控件；只要栅栏存在、内容损坏或读取失败，就停止旧路径并提供原始记录和当前页面进度的导出。旧版保存、上传、下载和恢复入口也检查对应标记或栅栏，其他账号互不影响。浏览器专项验证事务失败、强制终止及重启、本地标记缺失、栅栏值损坏和账号切换。 导出独立读取准备记录、旧同步记录和旧槽位；任何一份读取失败时，仍导出其余可读记录，并在文件的 `unavailable` 字段及页面中提示缺失项。浏览器专项分别注入新存储和旧同步存储读取故障，验证另一份副本仍可导出。

恢复页提供取消未完成切换：仅当新主记录、旧槽位及原始同步基线仍一致时，在账号和同步锁下将取消回执写入严格事务，再移除本地标记并严格删除栅栏；任一步失败时保留可核对的回执或栅栏，页面重启后可重试。已发生新存档修改、旧槽位或同步记录变化、标记不匹配时拒绝取消。专项覆盖分叉拒绝、两处事务故障、浏览器强制终止后重试和旧数据保留。旧 localStorage 槽位在强制终止前经过等待，不证明它具备严格持久性；取消完成回执与栅栏删除在严格事务中同时提交，启动时若旧标记重现，只有回执 nonce 匹配且不存在活动栅栏时才在账号锁内清理。标记不匹配、回执损坏或锁不可用时仍要求核对。候选副本保留以供核对，并不自动成为活动存档。

栅栏目前只由内部组件创建，尚无面向用户的激活或自动恢复流程，普通账号学习仍使用旧槽位；这并未解决旧存储进程终止后的丢失。旧客户端不遵守新栅栏；本地标记丢失且 IndexedDB 不可用时也无法识别既有栅栏，必须继续解决兼容和故障恢复，不能据此声称切换已安全完成。

## 普通账号旧槽位差异的确认恢复

严格主存档与迁移旧槽位不一致时，不自动猜测差异来自存储回退还是旧客户端修改。用户可先导出记录，并明确选择恢复迁移时的旧槽位：持有账号和同步锁，确认旧增量记录仍与迁移证据一致，将当前旧槽位原文和时钟及恢复意图在严格事务中保存，再恢复迁移时的旧槽位和时钟。恢复中断后，只接受意图记录的原值或目标值，遇到第三种值保留并拒绝覆盖；完成后清除意图，独立旧槽位备份仍可从本机记录导出。备份上限为八份，达到上限须导出并人工核对。恢复意图存在时不允许继续学习或取消切换。此操作不会自动合并旧槽位的不同修改，界面在确认前明确说明。

专项覆盖备份事务失败、部分 localStorage 写入失败、浏览器强制终止后重试、意外第三种值及旧同步记录变化；Web 恢复后写入服务器，再由 iOS 读取并更新，最后 Web 读取的模拟器联动通过。localStorage 仍无严格落盘承诺，恢复后再发生回退时可能需要重新确认；旧客户端可绕过锁，网络提交和本地写入无法跨设备原子化，真机与物理断电仍未验证。

## 恢复后旧槽位重现

普通账号完成迁移和超限恢复后，浏览器进程终止可能使未落盘的 localStorage 删除回退，旧槽位重新出现。启动时若存在经验证的大状态主记录，且旧槽位与严格持久化的恢复前备份完全一致、没有待恢复意图、迁移记录或旧增量记录，则在账号和同步锁内再次删除该重复槽位；内容不一致、记录损坏或锁不可用时保留旧槽位。浏览器测试构造旧槽位的相同和不同内容，并覆盖完成恢复后的进程终止。旧客户端不遵守锁，且 localStorage 的再次删除仍不具备严格持久性；同样的旧副本可在下次启动再次清理，不等于普通存档持久化问题已解决。

## 最新进展：Web 实验性大状态学习

服务器显式启用实验能力后，Web 在首次读取超限时可保存经校验的分页快照，并由用户主动选择使用该副本学习。学习修改先写入严格持久化的 IndexedDB 日志，确认提交后才发送评分请求；持有账号独占锁的页面可上传日志并手动拉取服务器变更。曾选择使用副本的账号在浏览器重启后会尝试自动恢复：独占锁、账号、主记录、基线和日志仍逐项校验，联网时重试上传；偏好或副本损坏、账号发生变化或其他页面持锁时保留恢复界面。保存失败时保留页面中的修改并提示导出；同步期间检测到本机状态变化时拒绝安装下载结果。

同步期间返回的后台评分可排队等待同步结束后落盘。如下载事务已经提交并改变基线，仅在本机变更是已持久化的待评分事件完成、且服务器没有修改对应卡片和相关参数时，才将完成结果重放到新视图，严格落盘后继续同步。比较时兼容服务器省略空评分版本映射；其他同卡、参数、多个排队修改或保存失败仍停止并保留页面供导出。重新加载可从日志恢复已提交的合并结果。这不是一般冲突合并。

合并还校验原评分历史的事件及顺序、既有已应用事件和参数版本均保留；待评分事件必须恰好进入已应用集合，并与历史记录中的参数版本一致。所有引用的参数快照必须可用且与服务器新视图一致，除非该版本是本机新增且服务器也尚无该键。缺少证明或出现不一致时保留原视图，不自动合并。

## 实验性分片恢复基础

服务器在实验开关启用时声明 `experimental_large_restore_v1`：客户端可复用账号隔离的分片暂存上传最多 14 MiB 的状态，以代次、基线修订和恢复版本为条件提交。验证完成后同一事务备份原状态、安装新状态、递增恢复版本及修订、写入重置标记和回执；失败回滚全部变更。回执绑定批次、基线和备份摘要，可在暂存清理后查询；过期、代次轮换或服务器后续变化时不能据此假定它仍是当前状态。备份回滚工具轮换代次时清除回执和暂存。

Swift 同步协调器可在账号锁内核对已同步的本机视图和基线，先将账号专属栅栏、完整恢复意图、原视图及基线摘要原子写入并同步文件与目录，再发送分片。恢复记录或栅栏存在时普通同步拒绝继续，即使其中一项缺失或损坏也不解除保护；重试时须再次核对原视图、基线、账号和回执。记录有内容及元数据摘要，读取有上限，保留原始记录以供后续恢复。协调器另可根据回执固定快照修订，校验恢复版本、解析独立评分参数，并确认服务器水位及本机基线、恢复记录仍未变化；所得结果只是待安装候选。iOS 设置中可导出未超过 40 MiB 的原始恢复记录，即使记录内容损坏也不必先解码。此路径尚不能安装恢复后的本机状态或清除栅栏，也未接入启动恢复；调用方不得在仅获得历史回执后假定服务器仍处于该版本。Web 和 iOS 恢复界面尚未接入，用户导出的超限文件尚不能直接在应用中恢复；服务器仍整体处理状态，实验开关保持关闭。该基础不是完整的双端超限备份恢复。

iOS 同步协调器增加了安装前候选记录：在核验服务器快照后，将目标学习视图、服务器基线、账号、版本及摘要持久化并同步到磁盘，再调用主线程安装回调。回调必须检查当前视图仍为原视图或已经是同一目标；重试须重新核验服务器水位、恢复意图和旧基线，并拒绝不一致的候选。恢复记录、保护文件或候选文件任一存在时均阻止普通同步。跨端测试在写入测试主存档后强制终止进程，随后重新创建协调器重试；候选损坏及孤立候选均不会解除保护。当时只实现协调器和测试回调，尚未接入应用实际主存档、增量基线替换或栅栏清除；后续基线进展见下文。

iOS 协调器现在可在检查目标主存档后，以同一主线程操作替换增量基线；仅接受与恢复意图摘要一致的原基线，或与候选完全一致的已安装基线，并同步基线文件及目录。每次重试检查服务器当前修订、恢复记录和安装候选；进程在基线写入后终止时可重复确认，不会再次替换不同的数据。恢复保护仍不清除，实际应用主存档和恢复界面尚未接入，断电及跨进程并发未验证。

iOS 协调器增加可中断的清理步骤：核对已安装的目标视图和基线，持久化恢复前本机视图及自包含完成记录，再依次删除临时记录；最后删除完成记录，期间每一步都保留同步栅栏并可重试。调用方必须在检查时同步主存档、署名文件和目录；目前没有接入应用实际存档和启动流程。隔离跨端测试分别在三个删除步骤后强制终止并恢复，最终允许读取新基线，且原视图归档仍在。测试包含超过 8 MiB 的服务器状态，macOS 测试进程采样峰值约 817 MiB（包含测试自身持有的多份数据），不能据此推断真机用量或可行性；需优化内存、避免长时间阻塞主线程并完成设备验证后才可接入。完成记录损坏或清理时服务器水位变化会保守阻止继续，仍需恢复和导出界面。

JSON 键冲突检查现直接扫描原始 Data，不再复制整份输入，也不为非键字符串重复创建解码副本；完整 JSON 解码仍负责验证值的转义、UTF-8 和语法。主机与模拟器专项覆盖重复键、Unicode 等价键、非法转义、控制字符和带非零起始位置的数据。相同大状态跨端脚本的单次 macOS RSS 采样峰值由此前约 817 MiB 降至约 717 MiB；两次均包括测试自身持有的多份数据，采样不能证明生产内存或稳定的性能改善。仍需减少恢复记录的重复物化、避免阻塞主线程，并在真机测量。

清理阶段先完整核对完成记录和其余文件，再以 256 KiB 分块计算摘要，在各步骤检查记录、归档和已删除文件是否变化，减少清理循环内重复解码。模拟器和跨端专项验证归档、完成记录及已删除文件被改变时继续封锁，以及进程终止后的重试。按上次同一场景单次采样，macOS 测试进程峰值约 779 MiB（前次约 717 MiB），未观察到进程峰值下降；测试持有多个状态副本，不能推断真实设备内存或证明优化效果。该路径仍需降低整体峰值、减少主线程工作并完成真机验证。

iOS 设置页现可重试已持久化的大状态恢复：识别待安装、已安装基线及部分清理阶段；每次写入或清理前核对账号、页面、内存进度和签名本机存档，最终同步存档、署名及目录。恢复前视图归档可通过现有本机备份导出；原始意图已被清理时可导出剩余完成记录或安装记录（受 40 MiB 读取上限约束）。模拟器界面验证了无待恢复记录的提示，隔离跨端测试验证了阶段识别及部分清理后的记录导出。尚未验证实际应用内从中断恢复到完成的完整界面流程；新建超限恢复入口、Web 恢复、主线程与内存优化及真机验证均未完成。上述旧阶段未接入实际存档和导出入口的描述以本段为准。

新增真实 iOS 模拟器恢复回归：隔离服务提交超过 8 MiB 的恢复并保留原本机槽位，应用登录后通过设置页继续，核验新基线、栅栏清理和恢复前备份，再由 Web 读取同一服务器状态。另一个模拟器场景在重试前修改本机设置，验证冲突提示、修改和保护记录均保留。成功场景中应用进程单次采样超过 500 MiB，仍须优化内存和主线程耗时；模拟器并非物理断电或真机验证。测试已加入 CI 配置，托管 CI 尚未运行。新建超限恢复和 Web 恢复入口仍未完成。

iOS 现可在服务器明确启用实验能力时，使用文件选择器预览并恢复超过 8 MiB、最多 14 MiB 的备份。预览检查严格 JSON、账号、服务器能力和恢复版本；确认后先保存当前本机备份和持久恢复意图，再分片提交并进入可重试安装流程。服务器未启用时拒绝，提交结果不确定时提示保留备份并继续恢复。模拟器从文件导出备份、修改并同步设置、导入备份到完成恢复，验证恢复前状态已留存；Web 随后读取同一服务器结果，普通小备份恢复及能力开关专项也通过。恢复前必须先同步本机基线；文件读取受限且游客仍为 8 MiB。超限恢复默认关闭，内存和主线程耗时、实际发起后强制终止、真机和真实断网仍需验证，Web 发起恢复尚未完成。此前“iOS 新建超限恢复未接入”的阶段描述以本段为准。

新增 iOS 实际发起恢复后的中断回归：从文件选择器导入超限备份，在隔离服务器事务提交而回执被延迟时终止应用；重启、重新登录后通过设置页重试，验证服务器修订不重复递增、本机新基线和恢复前备份均正确，随后 Web 读取相同结果。测试已加入 CI 配置，托管 CI 尚未运行。此测试是模拟器进程终止，不代表物理断电或真实网络测试；主线程耗时和内存仍需优化，Web 发起恢复仍未完成。

Web 增加实验性恢复传输组件：校验账号、能力、备份长度和摘要，先查询已有回执，再分片上传并核对回执；账号切换、不同备份使用同批次、错误回执及服务器代次变化均拒绝。隔离浏览器测试在服务器提交后关闭页面，由测试框架重新提供同一意图进行重放，Swift 校验恢复快照。此组件尚无 Web 持久恢复意图、同步栅栏、恢复安装或用户界面；测试框架暂时代持意图，不能证明浏览器重启后用户数据可恢复。服务器开关默认关闭，不应直接从产品流程调用该传输。

Web 恢复传输还固定了调用方传入的意图字段，避免异步等待期间对象被修改后把未持久化的字段发给服务器；浏览器专项覆盖请求中修改意图、能力关闭和摘要损坏，均保持安全行为。该传输仍未接入持久化意图、栅栏或界面。

这仍不是完整大状态协议：冲突和历史过期不能自动解决，超限备份恢复与历史整理仍为默认关闭的实验功能，服务器仍整包处理且实验容量有限；真机、真实网络及全部升级路径尚未验证。实验开关默认关闭，不应在生产环境启用。下文保留各阶段的设计记录，涉及“尚未接入学习界面”的描述属于当时状态，以本节为准。

状态：设计中。服务端已有独立的固定快照分页接口和事务内递增的 `state_revision`，并已记录持久化状态的有界变更日志，Web 和 iOS 已在有可信基线时使用有限的增量上传；双端已在有可信基线的部分普通同步中读取日志，完整同步游标尚未实现。两端回退路径仍上传整个学习状态，Web 和 iOS 回退读取仍下载整个状态，服务端对序列化状态限制为 8 MiB；超过上限的本机分支仍需导出并人工处理。不要将现有整包字段任意分组后直接调用 `merge_learning_states`：该函数需要整份状态的恢复版本、定级版本、日志和因果证据，部分字段的缺失可能被理解为旧客户端、空后验或重置。

## 目标和约束

- 正常学习只传递自上次确认以来发生的变更；可在服务端和客户端状态超过单请求大小时同步并分页下载。所有页须属于同一可验证快照，不能在分页途中把不同版本拼成状态。
- 同一账号的独立设备可离线评分、断线重试并乱序到达；事件有稳定 ID，重传幂等。FSRS、词级和分档知识、后验因果关系及每日记录按现有证据规则合并，不能把重复上报视为新评分。
- 恢复或历史整理必须切换恢复版本。旧版本的离线修改不可静默写入新基线，应保留本机分支并提示导出及冲突处理。
- 旧整包客户端不能读取截断的状态、覆盖新协议数据，或与迁移任务同时绕过一致性检查；无法安全支持时应返回明确升级或冲突错误。服务器升级先于客户端升级。
- 上传、下载或本机落盘中断时，本机已确认数据和未确认修改均可恢复；不能仅因某一批返回成功就标记整个本地快照已同步。

## 当前修订号的范围

`GET /api/v1/me/state` 对没有存档的账号返回 `state_revision: "0"`，已有存档返回十进制字符串，并在同一数据库事务读取 `sync_generation`。Web 建立基线时要求普通读取与原始快照的修订号及代次均一致。旧版整包 PUT、首次读取时固定旧证据基线、恢复与整理，均在写事务中推进存储状态的修订号；失败事务不会推进。字符串避免 JavaScript 安全整数上限造成精度损失，现有 `updated_at` 和旧客户端流程保持兼容。

这个修订号只覆盖 `account_state` 中持久化的 JSON。GET 响应还可能从独立的参数数据库补充 FSRS 配置，因此当前修订号不能证明完整 GET 响应不变，不能作为分页快照、条件写入或幂等游标使用。数据库回滚也可能回退修订号；受支持的恢复流程会轮换同步代次，手工恢复必须按 README 停写并显式重置。真正用于完整同步前，仍须解决独立参数、旧进程并发写入和协议迁移。旧版服务与新版服务不得同时写入。

## 恢复与整理的回滚保护

新版客户端读取到代次和修订号后，使用独立的 `guarded-restore`、`guarded-checkpoint` 接口，服务器在同一写事务中同时核对代次、修订号及原有时间戳。即使数据库回滚后时间戳和修订号碰巧相同，旧代次的预览仍会被拒绝；缺少全部版本字段的旧服务使用旧接口，部分字段缺失时客户端拒绝操作。受支持的数据库恢复必须轮换代次。Web 会在同账号锁内先保留待同步目标，仅服务器成功后清理基线；iOS 同样先执行条件操作再归档清理。旧客户端直接调用旧接口时无法获得此项代次保护，部署仍需升级客户端及停写演练。

普通拉取也不得把已知旧代次、旧恢复版本或倒退修订号的结果覆盖本机：双端在已有增量记录时先核对，再应用服务器状态；待确认批次或记录损坏时保留本机进度。Web 在检测到其他设备写入或受保护合并完成后保留原基线，而不是清空后退回旧 PUT；正常拉取可建立新基线，此前再次编辑会通过受保护合并处理。记录标记存在但 IndexedDB 记录缺失时拒绝退回旧写入。iOS 增量记录有独立持久标记：记录丢失或标记损坏时拒绝普通同步，旧记录在读取时补标记；用户明确确认重载时，可在告知丢失的待同步内容无法找回并备份当前本机状态后清除缺失记录的标记。两端在完全丢失所有本机代次记录后仍无法识别历史回滚。这些回滚校验本身不实现增量读取，也不能阻止读取完成后立即发生的服务器回滚。

## 本机替换与同步记录清理

Web 恢复、整理和显式重载在同账号锁内处理：异步删除旧基线时保留标记，随后的本机校验和替换在同一 JavaScript 执行片段中完成；本机变化或写入失败时标记继续阻止退回旧上传接口。服务器支持版本保护但浏览器不支持增量存储时，操作开始前也先保留标记，避免响应丢失后失去保护；若该环境之后仍无法访问增量存储，可能需要导出并人工恢复。iOS 重载将本机校验、保存和清理放在主线程的同一同步步骤内，并先保存替换结果、后归档和清理旧记录；保存失败时不清理保护。跨文件落盘与进程崩溃仍不是单个事务，备份和旧记录保留不能代替完整的崩溃恢复协议。

## 已提供的快照基础接口

认证后 `POST /api/v1/me/state/snapshots` 默认固定一次完整 GET 响应；指定 `?representation=stored` 固定持久化的原始状态及其修订号，不从独立参数库补全。清单明确返回快照类型、数据库同步代次、不透明 ID、恢复版本、字节长度、页数和 SHA-256；`GET /api/v1/me/state/snapshots/{id}?page=0` 按零起始页返回 base64 字节，`DELETE` 显式释放。页固定为 128 KiB，快照上限 16 MiB，每账号最多三个、全局有效快照载荷最多 128 MiB，十分钟后不可读取；恢复或整理改变恢复版本后旧快照不可读取。快照包含创建时取得的 FSRS 参数副本，即使独立参数库后来改变，各页仍属于同一份内容。创建时可提供 `Idempotency-Key`（每次操作随机生成的 32 位小写十六进制标识）；同账号并发或超时重试在快照仍存在时返回同一份清单，不额外占用名额；不同账号相互隔离；同一账号同一标识被用于不同快照类型时返回 409。普通写入不会改变重放结果，恢复版本改变会拒绝重放。快照显式释放或恢复后，服务端移除可读载荷并保留请求标识直到原到期时间；期间迟到重试分别返回 410 或 409，不会创建新快照；代次轮换会清空全部标记，旧标识可能创建新快照，客户端重试必须比较清单代次并拒绝将其当作旧结果。每个账号最多保留 64 个未过期请求标识，避免反复创建和释放导致标记无限增长。过期记录尚未清理时返回 410，清理后同键可能创建新的快照；客户端必须在过期后使用新键，也不能把键作为长期同步游标。调用方必须处理 409、410、413、429、503 和过期并主动释放不再需要的快照。

快照保存在 users.db，因此现有数据库备份也可能包含这些临时数据并增加备份体积。过期只立即禁止读取；记录清理发生在后续通过版本校验的快照创建时；显式释放或恢复清理会先使载荷不可读，带幂等键的记录保留至到期，空闲服务没有后台清理。数据库文件及 WAL 可能仍包含被移除载荷的残留，不能视为安全擦除。限流当前按进程和来源 IP 生效，反向代理及多进程部署仍需部署层限流。分页及哈希只保证取回创建时的同一份内容；读取期间其他设备可能写入，页面返回后也可能发生恢复。未来客户端提交本地结果前还须处理本地并发修改、重新确认版本和恢复代次，不能仅凭读取完成覆盖当前进度。

## 已提供的状态变更日志

现有整包 PUT、首次固定旧证据、恢复和历史整理在更新 `account_state` 的同一 SQLite 事务中写入变更日志；旧库迁移已有状态不会伪造之前的历史。普通写入记录顶层字段和映射条目的 set/remove 操作（数组整体替换），按账号和修订号保存；记录过大、恢复或整理产生重新建立基线的标记。最多保留每账号 32 条及 16 MiB 载荷，全部账号最多 128 MiB 载荷；条数、容量淘汰以及服务回滚都会使旧水位失效。

`GET /api/v1/me/state/changes?after=<十进制修订号>&generation=<快照代次>&page=0` 返回下一条已提交变更的页、总字节、SHA-256、该次提交的更新时间、恢复版本和当前存储修订号。客户端必须取齐同一条记录的所有页并验证后再原子应用；路径是原始 JSON 字段数组，JavaScript 实现必须安全处理 `__proto__` 等键，不能通过普通对象属性赋值造成原型污染；409 表示版本回退或恢复边界，410 表示所需历史不可用，必须重新获取可信基线；当前记录为最新时 `change` 为 null。服务端响应禁止缓存。日志只覆盖存储的状态 JSON，不包含独立 FSRS 参数库的变化；必须使用 `representation=stored` 快照作为变更日志基线，默认补全参数的快照不能直接作为该基线；独立参数可按指纹解析，但客户端仍须检查缺失并安全保存。备份工具恢复现代数据库时会为暂存副本轮换代次并清理临时快照和日志，旧代次即使修订号相同也被拒绝；旧数据库迁移时生成新代次。手工恢复或直接复制数据库必须在停写后显式执行 `reset-sync-generation`，绕过该步骤无法防止修订号重用。此接口仍不能替代完整同步协议。日志、临时载荷与状态同库并可能进入现有数据库备份；载荷上限不计数据库索引或记录元数据。

## 有界增量上传基础

`POST /api/v1/me/state/deltas` 接受 `generation`、十进制字符串 `base_revision`、整数 `restore_epoch`、随机 32 位小写十六进制 `batch_id` 和 `ops`。每个操作是 `set` 或 `remove`，路径由零至两个 JSON 字段组成：空路径只能单独替换完整对象；顶层字段和映射项可分别设置或删除，数组整体替换。重复或重叠路径、缺失的删除目标、恢复版本修改及无效内容会拒绝。单批最多 2048 个操作、规范化后最多 2 MiB；因果依赖和相关评分必须在同一批内完整且可校验，不能依赖中间半状态。

服务端在同一写事务中核对数据库代次、恢复版本与当前存储修订号，将操作应用于私有副本，再执行与旧整包 PUT 相同的验证、合并、写入及变更日志。并发或旧客户端写入造成基线不符时返回 409，不自动覆盖；客户端应保留未确认修改、重新拉取并按既有证据规则解决冲突。账号内同一批次标识和相同内容重试返回原提交回执；不同内容返回 409。回执每账号最多保留 256 条，七天后不再用于幂等重放，物理清理发生在后续成功提交批次时；过期后旧请求因基线已前进而被拒绝，客户端不得重复使用过期批次标识；数据库代次或恢复版本改变时旧批次不可重放。成功回执只表示该批次已提交，客户端仍须处理并发变更和本机修改，再确认自己的同步水位。

Web 已在可验证基线存在时使用该接口：IndexedDB 按账号保存服务器基线、用户上次视图和发送前待确认批次；恢复页面后重放相同批次，校验服务端变更并以跨页面锁串行化。普通并发基线冲突、补丁无法表示或超过暂存上限时，先保存待确认目标，再使用同代次、同恢复版本的整包合并；大于单次请求上限但在暂存限额内的批次使用分片，响应丢失后可重试。已有基线时不回退到无代次保护的旧式 PUT；旧服务或无可用基线时维持原有整包流程。代次变化、校验失败和无法保存待确认批次时不会确认同步，待同步快照可在设置中导出。iOS 已能解码响应中的字符串修订号与代次，并实现独立的原始快照分页读取：核对普通读取的代次和修订号、逐页长度及 SHA-256，检查账号切换并尽力释放快照。并提供独立的本机视图差异生成与批次提交方法，校验回执并识别结构化基线冲突；还可按回执读取对应服务器变更，校验所有分页和哈希后应用到原始基线，拒绝重置边界及无法安全匹配的字段路径。解析基线必须使用带键冲突检查的入口：Swift 字符串字典会折叠 Unicode 规范化后相同的不同 JSON 键，无法安全表示的键或数字必须拒绝，不能默默丢弃或舍入。并提供独立的本机原子记录存储：按账号保存服务器基线、用户视图及发送前待确认批次，验证回执后一次性替换记录，清理前导出待确认目标；并提供独立协调器跨异步等待串行化同账号的基线和上传操作，支持持久重放及受保护合并。上述方法、存储和协调器已接入 iOS 登录、自动同步、手动同步及恢复；待确认目标可导出，条件恢复或整理成功后才归档并清理同步记录；现有学习状态的 8 MiB 存储限制仍然存在，超过状态上限的大状态、多批次持久续传、自动冲突重基线、参数依赖及跨设备因果完整性尚未完成。分批提交不得被描述为已经实现完整增量同步。

状态、快照和参数接口的成功与已处理错误响应均标记 `Cache-Control: no-store`；双端状态及变更请求也绕开本机缓存。否则浏览器可能复用可缓存的 410，掩盖此后数据库代次变化。

## 多修订号读取与参数解析基础

Web 和 iOS 提供独立的多修订号日志读取方法：首个响应固定目标修订号，逐项校验代次、恢复版本、页清单、长度和哈希，在私有副本应用变更；并发追加不会改变目标，水位回退或变更不可用时拒绝。两端另提供引用参数解析方法，向账户隔离的参数接口查询所有引用，缺失或与已有版本冲突时拒绝。iOS 当前为复用已验证的提交回执读取逻辑，会对每条变更多发一次请求。iOS 已在登录和前台普通同步中使用这些方法；旧服务或日志过期时仍回退整包读取。iOS 在账号记录中先持久化原视图、目标视图和新水位，再保存主槽位并确认；重启会在推送前恢复暂存，安装前重新检查代次，版本不符或本机另有修改时保留记录并拒绝。Web 也已接入普通同步：先在 IndexedDB 保存原视图、目标视图、服务器基线和新水位，再写入本机槽位并确认；刷新、缺失主槽位、切账号或本机修改时恢复或保留暂存，日志过期时回退整包。标签页会核对共享槽位以避免将已知其他页面的修改标成同步完成，但 localStorage、IndexedDB 和不同标签页之间仍不构成单一原子事务。iOS 暂存记录有独立的 32 MiB 上限，多个完整副本与 base64 开销可能使接近现有限额的状态仍无法暂存；跨文件不是单个硬件事务，整体状态也仍受 8 MiB 限制。不能据此宣称完整增量下载已完成。

原始存储快照通过单次事务读取已锚定的存储修订，不再先执行完整状态的调度参数补全再重复读取；快照插入时仍核对代次与修订号。普通状态读取与补全快照仍按原规则附加可用的调度参数。对于数据库中已存在且无需新增旧证据锚定的超限状态，原始及补全快照可在 16 MiB 快照上限内分页读取；旧整包 GET、整包写入及当前增量写入保守返回 413，避免旧端覆盖。判定使用规范化 UTF-8 字节数，而不是数据库文本的转义长度；旧式 GET 也检查补全参数后的大小。该路径仍在内存中序列化完整状态，无法让当前客户端创建或正常同步超过 8 MiB 的状态；需要额外锚定的超限旧状态仍受写入上限约束，尚不构成完整方案。

## 大批次暂存（服务端基础）

`POST /api/v1/me/state/delta-stages` 接受批次标识、同步代次、基线修订号、恢复版本、完整 JSON 操作数组的字节长度、分片数及 SHA-256。每片通过 `PUT /api/v1/me/state/delta-stages/{batch}/parts/{index}` 提交 base64，分片按 256 KiB 定长（末片除外）；相同内容可重试，不同内容不能覆盖。所有页齐全后 `POST /api/v1/me/state/delta-stages/{batch}/commit` 校验完整字节、JSON 和所有操作，再使用原有增量事务进行幂等提交；不能绕过基线、恢复版本、代次或事件验证。读取、删除和提交只对所属账号开放；提交事务再次核对暂存实例，删除后旧请求不得提交新建的同名暂存。客户端在收到并持久化成功回执后可 `DELETE /api/v1/me/state/delta-stages/{batch}` 释放；删除后该暂存不能再用于重放回执。暂存与分片保存在用户数据库，最长一小时，每批最多 16 MiB、每账号最多三批及 32 MiB、全局最多 4096 批及 128 MiB；过期在创建新暂存时清理，离线备份可能包含暂存数据，恢复或轮换同步代次时会清除。认证、账号/IP 限流和现有请求体限制仍适用。

该接口支持将超过 2 MiB 或超过 2048 项的单次增量批次原子暂存，最多 8192 项；旧单请求接口仍限 2048 项，变更日志仍以兼容旧客户端的最多 2048 项表示，必要时将整个映射合为一项。服务端暂存清单声明操作上限，两端遇到未声明该能力的旧服务时回退到受保护合并。最终状态仍受 8 MiB 上限，数组仍须整体替换。Web 已在普通增量批次超过单请求限制时使用该接口：发送前将完整批次和目标写入 IndexedDB，重启后先校验待发操作与持久化目标一致，再以同一批次和分片重试；收到回执并持久化服务器基线后才尽力释放暂存。旧服务返回 404 或基线冲突时使用受代次和恢复版本保护的合并。iOS 也已接入：发送前将操作数组的精确字节与批次、本机目标一起保存在按账号隔离的原子记录中，重启时验证操作与目标并重放原始字节；回执和服务器基线落盘后尽力释放暂存。会话切换拒绝旧请求，旧服务及基线冲突走受保护合并。隔离模拟器通过预置含 2100 张新增卡片和约 2.1 MiB 数据的待发记录，验证服务器已提交时终止应用并重启后重放不增加修订号，本机卡片与数据完整；该用例不覆盖真机或真实网络。iOS 完整记录仍有 32 MiB 限制，多个副本可能使接近 8 MiB 的状态无法暂存。超限状态的分项存储、跨批次因果依赖和真实双端回归均未实现。因此它不是超过 8 MiB 的完整增量同步。

分片上传的 iOS 本机记录只保存操作数组的原始字节及批次头，不再重复保存一份操作数组；载入时从原字节重建操作并校验键、内容和目标，重试仍发送同一份字节。新版能读取旧记录；持有新格式未完成批次时降级到旧版应用会因无法解析而停止同步，应先用新版完成或导出，不能删除待发记录。该优化不改变 32 MiB 记录限制，其他完整状态副本及 base64 仍可能导致容量不足。

iOS 增量下载暂存时保留原始旧视图字节及其 SHA-256，省去与其等值的本地基线副本；读取时校验摘要及 JSON 键，并从旧视图重建基线，之后仍执行恢复版本和视图检查。旧下载暂存记录仍可读；新格式尚未确认时降级旧版应用无法读取，应先用新版完成或导出。此方式仍保留服务器基线、目标和原视图，仍受 32 MiB 限制，不能保证所有 8 MiB 状态均可暂存。

显式恢复、整理或服务器重载需要清除待确认同步记录时，双端先将待上传目标或待下载的旧视图和目标视图归档为可导出的未确认数据；任一归档失败时保留原同步记录，阻止后续清除。Web 新归档按账号槽位隔离，历史上归属未确认的旧归档仍按旧规则显示；浏览器容量不足可能阻止操作，需要先导出并释放空间。iOS 恢复及整理在发送服务器请求前完成归档，之后只有记录字节未变化时才清除；服务器已处理但清理或会话校验失败时仍可能出现本机未完成状态，应保留归档并重新核对服务器。跨文件检查并非跨进程原子锁。

iOS 恢复和整理先在主线程核对会话和原视图并保存服务器结果，成功后才清除同步保护。没有现存记录时请求前建立缺档保护标记，无法确认结果时保留标记、阻止旧式上传；即使服务器明确拒绝请求，也可能需要用户核对并重载以清除此保护。服务器提交、本机文件保存和记录清除并非一个跨设备事务；异常时仍须导出并核对。

## 迁移期间的按条目镜像

状态达到 1 MiB 时，服务端在原整包 JSON 之外按顶层映射键及数组位置写入条目，并在同一事务中保存清单、修订号和 SHA-256；较小状态清除该镜像。读取及修改现有状态时校验标记、修订号、条目和整包镜像一致性，校验失败拒绝操作；写入异常回滚完整事务。备份恢复保留这些持久数据。迁移期间必须停用旧版写入程序，不能让它们与新版并行写入。

这是兼容迁移的冗余表示：仍保留完整 JSON，修改时扫描并比较全部条目，仅写入变化或删除的条目；数组以位置而非稳定事件 ID 标识，前部插入或删除仍可能改写大量后续条目，读写仍会加载完整状态。它增加数据库和写入开销，不解除 8 MiB 写入上限，也不提供独立条目的增量事务或超限状态同步。超限数据的自动迁移、按事件键更新与客户端完整支持仍待实现。

增量日志读取在 SQLite 读事务中检查当前状态与条目镜像；同一账号和修订的验证结果可在进程内短时复用，最多两秒。缓存不含学习内容；独立只读连接的 SQLite `data_version`、数据库及 WAL 文件的身份和元数据必须在建立读取快照前后保持一致，写入、文件变化、数据库替换或监测异常均使缓存失效或回退完整校验。磁盘静默损坏若不改变 SQLite 版本或文件元数据，可能直到缓存过期才被发现；这不是对任意硬件故障的即时检测保证。隔离 HTTP 测试中约 7.0 MiB、4000 条合成卡片首次读取约 77 毫秒，接下来五次约 3–4 毫秒；数字不代表生产性能，频繁写入会降低命中率，仍需容量压测。该缓存不能把现有实现变为可扩展的超限同步。

## 按指纹解析 FSRS 参数

`POST /api/v1/me/fsrs-schedulers/resolve` 接受快照代次 `generation` 和至多 256 个不重复的版本指纹 `keys`，只查询当前账号在学习状态中携带或独立参数库中持有的配置。返回经过规范化和指纹校验的 `versions`，以及明确未找到的 `missing`；配置损坏返回 409，参数库不可读返回 503。查找前后均检查数据库同步代次，跨代次读取返回 409。内容按 SHA-256 指纹寻址，客户端可在获取基线及每批变更后按实际引用补充参数；缺失、校验失败或代次变化时不得确认水位，应保留本机状态并重试或导出。

Web 和 iOS 在备份的全量参数接口超限时，已按引用版本使用该解析接口；双端普通增量读取均已接入。此接口不保证旧设备曾经未保存的参数能够恢复，也不保证已升级的 FSRS 算法库可重放历史版本。它不提供参数删除的因果日志，也不能代替原始状态基线、变更验证、客户端事务或增量上传。客户端读取后到最终落盘之间仍需检查账户、代次、本机并发修改及服务端状态，不能仅凭一次参数查询覆盖本机。

## 建议协议和存储方向

1. 为账号增加事务内更新的单调修订号，所有写入口（旧 PUT、增量提交、恢复和整理）都必须在同一 SQLite 事务里检查账号身份、恢复版本并推进修订号。不能依赖客户端时钟或浮点时间戳作为唯一版本。并发迁移须可重复执行并有回滚备份。
2. 把大集合按账号、恢复版本和稳定键拆为持久记录：词卡及其评分事件、词级/分档/后验证据、带 ID 的学习日志、待学及个性化任务等；标量、设置和定级版本保留明确的字段版本。增量提交须声明批次 ID、设备 ID、共同基线及事件集合。重复提交同一批次应返回原结果；相同 ID 对应不同内容必须冲突。
3. 批次校验必须在事务中完成。一个因果事件及其父依赖、相应评分和可验证的参数版本不能跨提交产生可见的半状态；允许分批暂存，但只有完整校验后的提交才能改变可见版本。缺乏共同基线、历史或参数证明的分叉继续返回冲突，不自动猜测合并。
4. 增量读取使用固定快照版本和不透明游标，按字节分页；快照失效、恢复版本改变或游标不属于当前账号时应明确拒绝并重新开始。客户端完成全部页、校验版本与内容并成功落盘后，才替换当前可见状态与确认水位；中间页和本地未确认事件保留以便恢复。
5. 迁移期间明确旧端能力：对低于整包限制的数据维持原协议，写入统一进入同一版本和合并管线；超过旧端可表示范围时拒绝旧端写入并提示升级，不能返回部分 JSON。不得直接提高单包上限当作增量同步。
6. 安全与资源限制按认证账号及设备生效：限制每页和批次字节、条目数、未完成暂存、重试及保留期；快照和游标不可跨账号使用。过期清理不得删除尚未确认的客户端数据，客户端继续保留并可导出。

## 验收矩阵

- 数千卡、长周期曝光和评分历史、超过 8 MiB 的状态：两端只传变更并可跨页恢复，杀进程或中断任一页后可续传或安全重试。
- 两设备同词和不同词同时离线：乱序、重复请求、超时后重试与并发提交均不丢事件、不重复评分，最终状态一致；缺失因果或参数时保留两端并报告冲突。
- 一端分页时另一端提交、恢复或整理：不得拼接不同快照；旧设备提交不得复活已恢复或整理前的数据。
- 新旧客户端混用、数据库迁移中断、备份恢复和回滚：兼容行为可重现；服务器及用户数据保持完整。
- 用户切账号、令牌失效、本机空间不足、413/429/5xx 和真实网络重连：状态及确认水位归属正确，失败后仍可导出和恢复。Web 真实浏览器与 iOS 模拟器及真机均须覆盖。

实施完成前不得把现有的整包压缩、分片暂存或历史整理描述为增量同步。

### 学习日志追加上传

支持 `GET /api/v1/me/state/delta-capabilities` 的服务可声明 `append_log_v1`。Web 和 iOS 仅在本地日志以前一视图为严格前缀、追加项均有唯一有效事件标识且服务器确认能力时，提交 `append_log`；旧服务器返回 404 时回退为原有整数组提交。每次最多追加 2048 项，旧记录、删除和修改仍按原协议处理。服务器检查事件标识，同标识同内容不会重复加入，同标识不同内容会拒绝；原有批次修订、恢复版本和幂等规则继续生效。

此优化减少常见追加操作的上传体积。服务端仍需读取、合并、存储完整状态；8 MiB 状态上限及本地完整副本仍存在。持有包含新操作的未确认批次时降级旧应用可能无法重放，应先用新版完成同步或导出。

### 日志精简下载

服务端在原有兼容日志之外为有利于缩小载荷的学习日志变更保存精简表示。新客户端请求 `compact=true`，并校验每一页的修订、恢复版本、长度和 SHA-256；旧客户端默认仍获取原表示。精简日志可追加带标识的记录，也可对固定基线的日志执行有边界的插入、删除和替换，以适应服务端排序及裁剪。新客户端拒绝越界或无效操作；历史记录没有精简表示时仍返回原格式。两种载荷均计入原有保留额度；容量紧张时可先淘汰某条记录的旧格式，保留精简格式，新端仍可读取该修订，旧端收到 410 并重新获取快照。容量进一步不足或超过条数上限时整个修订及其精简表示一并删除；旧服务忽略可选参数并返回原格式。

这减少可表示变更的下载字节数，不能消除旧格式的服务器存储开销，也不能保证在历史裁剪或大范围重排后仍有小增量。它没有解除 8 MiB 上限、整包合并或本地完整副本限制，不能视为完成超限同步。旧版服务与新版服务不得混合写入。

### iOS 待上传本机基线去重

存在待上传批次且服务器基线可以通过有界差异精确重建本机基线时，iOS 将差异及本机基线摘要写入原子同步记录，避免再次保存完整本机基线。加载时先应用差异、验证规范化字节摘要，再按现有规则核对批次和目标；无法安全表示、重建结果不一致或不节省空间时仍保存完整基线。旧格式可读取；新格式待上传记录未完成时降级旧应用可能无法重放，应先在新版完成同步或导出。

约 7.5 MiB 合成状态专项中，新记录在 32 MiB 限额内可落盘并恢复，之前保留两份基线的格式超过限额。压缩只去掉可验证的重复副本，不能保证所有大状态或冲突基线均能保存；同步记录上限、服务器 8 MiB 状态上限及客户端完整状态副本仍存在，不能视为完成超限同步。

### 实验性超限增量提交基础

服务端默认关闭实验入口。仅当进程环境明确设置 `VOCAB_EXPERIMENTAL_LARGE_DELTAS=1` 时，能力接口报告 `experimental_large_delta_v1`，并允许通过独立实验性增量入口提交有可信基线的修改；同一批次可使用普通请求或已有分片暂存的独立实验性提交入口。禁止使用空路径创建或替换整份状态，单请求操作仍受原有 2 MiB 上限，分片操作仍受 16 MiB 及 8192 项上限；状态本身暂限 14 MiB，以保留原始快照封套空间。代次、恢复版本、基线修订和批次幂等均在原事务中校验，不同入口的批次回执不能混用。旧整包读取、写入、增量、恢复和整理在超限基线时拒绝，避免旧端覆盖。关闭开关不会删除已存在的数据，旧接口仍会拒绝超限基线。

这是实验基础，双端已有可信基线的上传组件支持实验入口，但 Web 主存储尚未接入，不能用于生产迁移：客户端主存储、首次登录、冲突合并、备份恢复和完整大状态回归尚未完成。服务器仍会整体读取、合并和保存状态，现有条目是冗余镜像而非独立主存储；14 MiB 不是完整大状态协议的最终容量保证，也不应把这一实验视为已经实现按事件存储的完整增量同步。不要在生产环境启用该开关。

### iOS 待下载基线与视图去重

当下载的新服务器基线能从原基线通过有界差异精确重建时，同步记录保存该差异及摘要，并把前后视图的精确 UTF-8 字节按字符串保存，避免两个完整服务器基线和 base64 膨胀。加载时校验新基线摘要、目标视图摘要及原视图摘要，并继续验证修订和恢复版本。若差异不可安全表示、不节省空间或原视图不是可无损还原的 UTF-8，则保留既有格式；已有待下载记录仍可读取。新格式待下载期间降级旧应用可能无法重放，应先在新版完成同步或导出。

约 7.5 MiB 合成状态的小变更在 32 MiB 记录上限内可保存和精确恢复，旧表示超过上限。此优化不改变 8 MiB 现有客户端状态约束，不能保证所有数据或大范围变更均可暂存，也没有完成大状态同步。

### iOS 实验性大状态增量提交

已有可信基线的 iOS 账号在服务器明确声明 `experimental_large_delta_v1` 时，可对超过 8 MiB、最多 14 MiB 的状态使用实验性增量提交；超过普通请求大小时使用实验性分片提交。待发记录持久化所选协议，进程重启仍使用相同批次与入口，不能悄然改走旧接口。服务器不支持该能力、缺失基线、差异无法表示、版本冲突或所需变更被淘汰时保留本机进度并报告失败；不把大状态改为旧式整包合并。普通服务器仍使用原有协议和 8 MiB 写入约束。

该路径仍是实验性的：iOS 现可通过分页快照为全新设备建立部分超限状态的可信基线，但仍受本机记录容量限制；冲突尚不能自动解决，备份恢复仍受旧上限影响；Web 尚未支持超限本机状态，服务端仍整体合并并限制为 14 MiB。不要在生产环境启用服务端实验开关，以上能力不构成完整双端超限同步。

### iOS 实验性超限首次读取

旧整包接口返回 413 且服务器明确启用实验能力时，iOS 读取固定原始快照，验证分页长度、摘要、代次、修订、恢复版本和全部引用的评分参数；确认服务器水位仍为该修订后，首次登录先建立持久化同步基线，再保存主状态。快照损坏、账号切换、参数缺失或并发写入均拒绝安装。已有基线、日志已过期的回退路径也先验证并建立大状态基线，再更新本机槽位。若基线或槽位落盘失败则保留本机数据并报错；两个文件之间仍不是单一事务，异常中断可能需要用户重新同步或导出。

本能力受 16 MiB 快照、14 MiB 实验状态及 32 MiB 同步记录上限约束，无法保证全部接近上限的数据都能持久化；服务器仍整体加载和合并状态。Web 尚不支持超限主存储，冲突处理、备份恢复、真机与真实网络回归未完成。服务端实验开关应保持关闭，不应据此宣称完整双端超限同步。

### Web 大状态主存储实验基础

Web 提供独立的 IndexedDB 账号槽位原子读写组件，限定账号标识与最多 14 MiB 的规范 JSON；记录包含随机版本和 SHA-256，读取时完整校验。写入前校验调用方的已验证基线，并在同一读写事务中比较当前完整记录与预期，再提交新记录；两个标签页同时写入同一基线时至多一个成功，失败不会覆盖原记录。组件只在事务完成后报告成功；损坏、容量不足、版本冲突或中断时调用方必须保留尚未确认的本机修改。

该组件尚未接入现有学习主存档和同步流程，现有 `save()`、启动、账号切换及恢复仍使用同步 localStorage；不能因此认定 Web 已支持超限状态。接入前必须完成异步保存的提交确认、页面关闭和崩溃恢复、多标签页冲突导出、迁移回滚，以及旧槽位与新槽位的完整性和归属校验。

### Web 大状态写入日志实验基础

实验组件可在浏览器支持 Web Locks 时为一个账号持有独占写入租约。每次修改先以有界差异及前后 SHA-256 写入该账号的 IndexedDB 日志，要求浏览器支持严格持久化事务；调用方必须等待事务完成才可将该修改视为已保存；后续刷新把状态与日志提交标记放在同一 IndexedDB 事务中。中断发生在日志写入后、事务提交前时可从旧基线重建；发生在事务提交后、日志清理前时可通过提交标记识别已提交前缀，继续重放后续修改而不重复提交。持锁页面之外的普通组件写入在存在日志时会拒绝。损坏、冲突或日志超过 512 KiB 时停止并保留已有记录。

这是尚未连接学习界面的实验组件；它要求所有新主存储写入者遵守同一租约，旧页面不具备该保证。大范围单次修改可能无法用有界日志表示，IndexedDB 本身也可能不可用或配额不足。启动与迁移、异步保存的界面确认、冲突导出、实验同步协议接入和多标签页切换仍需实现；它不代表 Web 已支持超限状态或完整的离线崩溃恢复。

### Web 旧槽位迁移准备

实验组件可以在持有账号锁时，将旧账号槽位复制到独立的 IndexedDB 迁移候选区，严格事务完成后核对旧槽位是否变化；若已存在新主槽位、修改日志或检测到并发修改则拒绝。原 localStorage 槽位不被删除或替换，候选区也不会被当作有效主槽位。旧页面不遵循新锁，因此候选副本可能在事务后立即过时；后续迁移必须再次核对完整来源，并解决旧页面并发、进程中断、主槽位切换和回滚。当前没有自动切换流程，也没有连接学习界面；这只是迁移准备，并非完成迁移。

### Web 实验性超限上传组件

在已有可信增量基线且服务器声明实验能力时，Web 的增量上传组件可以为超限目标或基线选择实验性普通或分片入口，并将协议选择与待发批次写入严格持久化事务。丢失回执时以原批次和原入口重试；冲突、记录过期、服务关闭或无法表达差异时保留本机数据，不退回整包合并。浏览器专项以内存构造超过 8 MiB 的目标验证分片提交、丢失回执重放、关闭能力和冲突保留；Swift 客户端读取并校验了该 Web 上传生成的分页快照。这个专项绕过了现有 localStorage 主存储限制，不是完整界面或崩溃恢复测试。Web 大状态主存储和下载尚未接入，服务器实验开关应继续保持关闭。

### Web 首次读取保护和快照导出

新账号在当前设备没有可信存档时，先读取服务器，不创建空白账号槽位；只有确认服务器状态或确认服务器为空后才写入槽位。读取失败或服务器状态超限时显示恢复界面，阻止保存或上传。用户可以重试、切换账号、导出本页面内容及未确认旧存档；服务器明确声明实验能力时还可导出经分页长度、摘要、代次、修订、恢复版本、参数和最终水位检查的服务器快照。读取期间检测到新版页面尝试写入会保留冲突标记并拒绝安装；切换账号后不再导出旧账号的响应。浏览器被强制终止或等待标记丢失后，未确认的空白账号槽位不会被当作可信状态；现有旧版已经写入的占位槽位不具备这一保证。超限导出文件现阶段仍不能通过 8 MiB 受限的恢复界面直接恢复。

这是保护和导出路径，不是大状态安装：标记仍在 localStorage，尚不具备严格持久化保证；旧页面也不会遵守新标记。Web 主存储和大状态首次登录仍未完成，实验开关应保持关闭。

当新页面的首次读取与另一页面的未保存修改冲突时，用户可先导出相关页面的进度并关闭其他页面，再明确选择重新读取；只有账号槽位和增量同步标记均不存在时才清除冲突标记并重试。若已有槽位或同步恢复记录，界面拒绝自动覆盖，需要先导出并核对。该操作丢弃当前页面尚未保存的内存修改，界面会在执行前明确说明；仍不能约束不遵守标记的旧页面。

### Web 大快照本机恢复副本

恢复界面可将服务器验证过的快照保存为本机恢复副本。主内容和原始增量基线写入同一 IndexedDB 严格持久化事务；账号锁、同步锁、当前会话、旧槽位、既有日志和同步记录均在提交前检查，并再次确认服务器水位。离线导出前核对账号、版本、长度、摘要和恢复版本；损坏时拒绝当作有效学习进度，并允许导出未经校验的原始本机记录供核对。浏览器专项覆盖事务中途失败回滚、进程终止、离线导出、账号隔离及服务器和本机竞争。

该副本目前是恢复用途，不是活动学习主存档：学习界面、异步写入日志、增量下载和普通同步尚未接入。当前不能用副本继续学习；若服务器或本机在保存后变化，副本也可能不是最新数据。客户端仍有 14 MiB 上限，旧页面不遵守新锁；实验服务器开关应保持关闭。

实验性同步日志可在显式内部模式下持有该副本的账号锁，校验服务器基线和本机视图后记录小范围修改。首次提交时将修改前本机视图和摘要保留为独立上传基线；主状态、基线版本与日志提交标记在同一严格事务更新。进程在日志落盘后或状态提交后终止，重新持锁时校验并重放未完成日志；同步基线损坏或事务失败均停止并保留可导出的原始记录。内部路径已连接实验性增量上传：待发批次先持久化，服务器回执确认后在同一事务更新两个基线并清除批次；回执丢失或落盘失败时重放原批次，版本冲突时保留待同步内容。上传期间内部接口暂时拒绝新日志写入；保留下来的后续修改可在重放后另行提交。此能力尚未通过产品界面启用，也尚未接入自动增量下载与冲突解决；副本在正常界面仍为只读恢复数据。

内部实验路径也可在本机视图与已确认基线一致、且没有待上传批次时读取连续服务器变更，核对评分参数和恢复版本，并在单个严格事务中安装主状态及两个同步基线。损坏页、账号变化、保存失败、未上传本机修改或待发批次均拒绝安装；读取期间出现的新服务器修订留待下次下载。浏览器强制终止时事务要么全部提交、要么全部回滚。该路径尚未连接学习界面和自动同步，日志过期与冲突仍需用户导出处理，不提供完整双端超限同步。

### Web 实验性超限恢复及待验证边界

普通账号导入超限备份前，先在账号锁和增量锁下检查旧槽位、已确认增量基线及服务器水位。在严格 IndexedDB 事务中保存原视图、原增量记录、新主状态和恢复意图；之后持锁逐步移除旧增量记录与旧槽位，过程中若旧内容不一致则停止并保留记录。每个清理步骤可在重启后重复；安装结果时再以单个事务清除迁移及恢复记录。等待标记先于事务写入，但它不是持久性依据：若事务前中断且没有恢复记录，原槽位保留，用户可返回原进度；若标记丢失，启动时检查 IndexedDB 中的恢复意图或大状态主记录，避免使用旧缓存覆盖。普通同步也在增量锁内检查这些记录。旧客户端不遵守新检查，无法保证混用安全。

服务器启用实验能力时，已使用大状态副本或具有已同步增量基线的普通 Web 账号可从设置页选择最多 14 MiB 的 UTF-8 备份；检查重复字段、确认账号与本机进度后，在账号及增量锁下验证本机视图和基线，并用严格事务保存恢复意图。主要大状态写入事务及等待服务器界面检查恢复栅栏；数据库升级被旧连接阻塞时明确失败。重试持有两个锁，使用原批次获取或提交回执，读取匹配回执的服务器快照并复核水位；再以单个严格事务保存恢复前备份、主状态和服务器同步基线，并清除恢复记录。设置页可导出最新恢复前备份。浏览器进程在服务器提交后被强制终止的专项可通过界面重试，故障注入验证事务失败时原状态和意图保留。旧页面可能绕过新协议，实验开关仍应保持关闭；还需验证和完善：

1. 在账号独占写入锁和增量同步锁下，先核对活动主存档、同步基线、页面内容、账号与服务端代次；任何待上传批次、未落盘日志或无法证明已同步的修改都应阻止开始。数据库升级必须让旧版本连接退出，不能把升级失败当成没有恢复记录。
2. 用严格持久化的 IndexedDB 事务同时比较主存档、基线、日志、待上传记录和恢复记录，再保存不可变的恢复意图及恢复前视图。成功提交事务后才能发送任何恢复请求。所有可能修改大状态、日志、快照或基线的事务都必须在同一事务中检查恢复栅栏，不能只在进入页面时检查。
3. 重启后先检查恢复记录和摘要，再按原批次查询回执或重传；回执只证明提交，安装前仍须读取固定版本的服务器快照、解析调度参数、确认当前水位并重新检查本地记录及账号。不同标签页、旧客户端、离线和版本轮换都不得悄悄越过栅栏。
4. 在单个严格持久化事务中比较未变化的旧视图和恢复意图，保存恢复前备份、安装服务器视图及增量基线、清除意图和栅栏。事务失败或页面终止时保留旧视图和意图供重试或原样导出；不能先删除意图再安装状态。当前同步基线允许保存服务器未知字段，本机视图不能代替服务器原始基线。
5. 等待服务器界面现可继续恢复、导出原始记录及切换账号，并提示服务器可能已提交；设置页可发起实验性恢复和导出恢复前备份。仍需更多冲突及异常界面、真实网络、真机和旧客户端混用验证。进程终止不等于物理断电，服务器水位检查与本地事务并非跨网络原子操作。
