# 核心学习策略 v1：实施与验证

本轮保持 py-fsrs 6.3.2 和 90% 目标保持率，修正产品资格判断、证据保存、显示统计和训练发布门槛。长期记忆效果需要真实数据跟踪；测试通过不代表算法永久最优。

## 数据与兼容

- `CardState.studyEvidence` 独立保存 `version/originAt/legacy/originIds/events`。事件包含时间、学习日、评分、作答类别、是否验证及上一次练习时间。与 FSRS 核心历史分离，避免旧客户端删除未知上下文造成调度分叉。
- `originIds` 标识迁移前的事件；升级后的未知旧客户端评分保守标记为未验证，不能贡献新掌握，但遗忘仍能撤销旧掌握。合并保留已有上下文，实际冲突仍拒绝覆盖。
- 同次评分的日志 `eventId`、FSRS `id` 和证据键一致，先持久化再请求。撤销使用评分前完整快照。
- `schedulerKey` 保存当前卡片参数版本，历史整理后仍能解释保持率；备份和增量下载包含其引用参数。
- `fsrsIssue` 隔离确定性坏卡；未完成评分仍完整保存并可重试，其他卡继续同步。
- `newSupply` 缓存词库版本、已扫描位置范围及未学习的可用词。版本或范围不匹配即失效，并始终计入待学词。
- `/api/v1/lexicon/meta` 提供词库版本与位置总量；`/lexicon/at` 返回版本及剩余位置。旧服务器无版本时不持久缓存“耗尽”。
- `/api/v1/fsrs/review` 对评分、状态、有限数值、范围、步骤和时间顺序返回带 `code/field/message` 的 422。旧日期精度仅在客户端能标记来源时兼容；精确时间矛盾不能静默修复。

## 验证范围

- 三端共享 20 个掌握生命周期夹具：新旧字段冲突、无效状态、仅有稳定度、三个间隔成功、即时验收、自评、未满一周、同日证据、困难、待应用成功、离线遗忘、跨端练习缩短间隔和旧掌握保留。
- Web 与 Swift 各 2,101 个离线阶段/步骤案例，对照安装的官方 py-fsrs；长期 Review 离线采用明确的临时 24 小时复查，联网后仍以原时间重算。
- 浏览器实际操作验证词库耗尽、到期按钮自动更新、100 个不同词与 110 次练习的互斥统计、猜测转遗忘、同一事件 ID、过期题目阻断和坏卡隔离。
- HTTP 验证旧客户端合并、日志裁剪独立性、检查点、离线遗忘、参数错误、并发领取最后名额及已发离线名额保护。
- 全套 HTTP/浏览器回归覆盖同步上传、下载、恢复、账号切换、重启、配额和磁盘故障；新增参数字段也纳入下载中完成评分的严格合并校验。
- Swift 原生 UI 覆盖学习/验收、遗忘/再现、共享计划重启、旧日期兼容；发布结果另记于 PROGRESS。
- 优化器在带 `fsrs[optimizer]==6.3.2` 的隔离虚拟环境中执行真实训练流程；测试额外验证样本不足、起点缺失、应用证明不完整、候选任一指标变差、原子写失败和旧文件归档。

## 一年负载模拟

执行 `python simulation/fsrs_daily_capacity.py --days 365 --seeds 7 17 27`。使用生产掌握评估函数、官方调度、每天 10 新词、100 个不同词上限、即时验收、分钟级重学与每天两小时学习窗口。未模拟可选探测；每词每天最多 30 次尝试是模拟保护，不是产品限制。结果是情景模型，不是个人记忆预测。

| 情景（三个随机种子） | 日不同词峰值 | 日练习次数峰值 | 积压峰值 | 年末积压 | 年末掌握 |
|---|---:|---:|---:|---:|---:|
| 按模型保持率回忆 | 90–100 | 120–125 | 24–28 | 10–17 | 1371–1400 |
| 回忆概率乘 0.85 | 100 | 182–186 | 1396–1501 | 1396–1501 | 596–657 |
| 回忆概率乘 0.65 | 100 | 264–269 | 2766–2819 | 2766–2819 | 128–165 |
| 正常回忆，中断 7 天 | 100 | 126–130 | 257–279 | 14–18 | 1337–1367 |

重复练习不增加不同词名额，因此练习次数可以超过 100。遗忘较多又坚持每天新增 10 个词时，100 个不同词的上限无法保证没有积压；产品保留真实到期记录、显示积压，不自动提额或删除记录。模拟原始汇总见 `core-study-capacity-20261030.json`。

## 发布与回滚

1. 完成回归及双端构建，备份源码、`users.db`、`personal.db`、词库、现有优化参数与参数归档；SQLite 使用一致性备份并校验。
2. 停止 API 写入，先安装兼容服务端。执行 `pipeline/migrate_study_policy.py --server-root <API目录> --apply --backup <全新备份文件>`。它为每个修改账号保留原始快照，递增普通状态修订号并写入增量记录；不改变恢复代次、调度或每日名单。重复运行无副作用。
3. 发布 Web、重启并核对健康与源文件校验和，再覆盖安装已签名的 iPhone 包。不要卸载用户原 App。
4. 回滚优先回滚代码；不要直接覆盖升级后已产生新评分的数据库。旧代码会忽略新上下文，服务端合并必须继续保留它。只有停止写入并核对升级后新增事件后，才可使用完整数据备份恢复。

完整训练已在隔离数据上验收；真实账号不满足有效样本门槛时不会强行发布新参数。
